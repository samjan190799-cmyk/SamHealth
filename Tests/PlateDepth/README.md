# Проверка замера блюда по глубине

Геометрия замера (`Sources/PlateDepthAnalyzer.swift`) не зависит от iOS и проверяется как обычный Swift-пакет:

```bash
cd Tests/PlateDepth
swift test
```

Исходник алгоритма подключён символьной ссылкой, поэтому тесты гоняют ровно тот код, который попадает в приложение.

## Что покрыто

Синтетические сцены строятся трассировкой лучей: стол-плоскость и цилиндры известного размера.

| Сценарий | Ожидание |
|---|---|
| Камера строго сверху | объём, площадь, диаметр, высота — в пределах 1% от истинных |
| Камера наклонена ~17° и ~9° | тот же размер, наклон не искажает объём |
| Расстояние 32 см и 55 см | объём не зависит от расстояния |
| Шум 3 мм и 5% пропусков | объём в пределах 12% (занижение из-за пропусков) |
| Блюдо больше рамки | флаг `objectTouchesFrameEdge` |
| Пустой стол, слой тоньше 12 мм | отказ `nothingOnTable` |
| Относительная глубина, нули вместо фокусного, пустая карта | отказ, а не выдуманное число |
| Блюдо занимает весь кадр (стола не видно) | отказ, а не замер от верхушки блюда |

## Чего тесты не проверяют — сверить на iPhone с LiDAR

Слой AVFoundation (`PlateDepthService.swift`, `BarcodeCameraViewController`) собирается только в Xcode.

1. Сканер открывается, штрих-код по-прежнему читается (сессия теперь с пресетом `.photo` на LiDAR-устройствах).
2. В режиме «Блюдо» HUD показывает живое расстояние, оно меняется при движении телефона.
3. Снимок тарелки известного размера (например, диаметр 26 см): в логе нет `Замер глубины отклонён`, а в запросе к ИИ есть блок «ИЗМЕРЕНИЯ ДАТЧИКА ГЛУБИНЫ» с диаметром ≈ 26 см.
4. Карта глубины совпадает по полю зрения с фото: измеренный диаметр не должен зависеть от того, в каком месте рамки лежит тарелка. Если зависит — глубина обрезана иначе, чем фото, и нужно скорректировать преобразование области.
5. С зумом ×2 замер пропускается, фото уходит без блока глубины.
6. Устройство без LiDAR: HUD пишет «Нет LiDAR • объём оценивается по фото», камера работает как раньше.
7. Фото из галереи уходит без блока глубины.
